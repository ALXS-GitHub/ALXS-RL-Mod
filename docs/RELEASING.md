# Releasing

Releases are built by GitHub Actions (`.github/workflows/release.yml`) and installed apps
update themselves from the latest published release.

## One-time setup

1. Repository secrets (*Settings → Secrets and variables → Actions*):
   - `TAURI_SIGNING_PRIVATE_KEY` — content of the updater private key
     (`~/.tauri/alxs-rl-mod.key`, never committed);
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — its password
     (`~/.tauri/alxs-rl-mod.key.password`).

   The matching public key is `plugins.updater.pubkey` in `src-tauri/tauri.conf.json`.
   Losing the private key means installed apps can no longer update: keep a backup.
2. GitHub Pages: *Settings → Pages → Source: GitHub Actions* (the website workflow
   deploys `site/`).

## Cutting a release

1. Bump the version in `package.json`, `src-tauri/Cargo.toml` and
   `src-tauri/tauri.conf.json` (same `X.Y.Z` everywhere), commit.
2. Tag and push: `git tag vX.Y.Z && git push origin main vX.Y.Z`.
3. The workflow builds the NSIS installer, signs the update and creates a **draft**
   release with `latest.json`.
4. Edit the draft notes (they show in the app's update dialog), then **Publish**.
   Installed apps pick it up on their next start (or *Settings → About → Check for updates*).

## Website

`site/` is plain HTML generated by `python site/build.py` (texts for EN and FR live in
that script). Pushing a change under `site/` redeploys
<https://alxs-github.github.io/ALXS-RL-Mod/>.

Search engines: submit `https://alxs-github.github.io/ALXS-RL-Mod/sitemap.xml` in
Google Search Console (paste its verification meta tag in the `<head>` template of
`site/build.py`) and Bing Webmaster Tools.
