# ALXS-RL-Mod — Architecture

Desktop app (Tauri 2 + React 19) to customise Rocket League **without injection and
without touching the network traffic of the game**. Everything is file-based
(cooked `.upk` packages, the native `CookedPCConsole/mods/` override folder) plus
the official Stats API.

> Research notes on the game file formats live in `docs_rl/` and stay forever.

## Principles

1. **Local first.** The item catalog is built from the user's own install
   (`CookedPCConsole/`) + a bundled product list. No catalog API, no CDN.
   Outbound HTTPS is limited to an allowlist of safe hosts (tracker.gg,
   bakkesplugins, Lethamyr) and only on explicit user action.
2. **Never intercept the game.** No certificates, no hosts file, no proxy.
   Spoof features that need traffic interception (fake ranks, titles, name…)
   are out of scope by design.
3. **Always reversible.** Every file we write into the game install is
   recorded in a manifest with the SHA-256 of what was there before and what
   we wrote. Restore verifies hashes. We prefer the `mods/` override layer
   (root file untouched) whenever the game honours it.
4. **Survive game updates.** A fingerprint of the install (`Engine.upk`
   size + mtime) is recorded when anything is applied. On startup, if it
   changed or if a verify pass restored stock files, everything is rebuilt
   from the *current* stock files (never from old backups).
5. **Typed everything.** Rust: `AppResult<T>` + `thiserror`, no stringly
   errors. TS: zod-validated IPC responses, no `any`.
6. **i18n from day one.** EN default, FR complete. No hard-coded UI string.

## Write layer — the only way to touch the game install

`game::writer` is the single gate every feature uses to write in the game
install (`install_file`, `restore_file`, `restore_owner`). It persists
`manifest.json` and `backups/`. Each entry records:
`owner` (feature), `path` (relative to the install root), `placement`
(`ModsOverride` or `RootReplace`), `original_sha256` (or `None` if the file did
not exist), `written_sha256`, `backup` (for `RootReplace`), `build_fingerprint`.
Restore refuses to overwrite a file whose current hash is neither
`written_sha256` nor `original_sha256` (someone else changed it).

Writes are refused while the game runs, except for `Owner::Maps`
(`writer::hot_swappable`): the game only opens a map when it loads it.
Maps are written over the Labs arena file itself (`RootReplace`, stock copy in
`backups/`), not into `mods/`: the game resolves package paths once at
startup, so a `mods/` file added later is ignored, while the stock path is
always known. Writing the arena you are playing on fails with `ArenaInUse`
(go back to the main menu). `maps::session::settle` removes stale map files
once the game has exited.

## Backend modules & public Rust API (cross-module contract)

```rust
// base

base::config::AppConfig  (+ ConfigState, get/update commands)
base::fsx::{sha256_file, sha256_bytes, write_atomic, copy_atomic}
base::security::{http_client(), ensure_allowed_download(url)}

// game
game::install::{current_install(app) -> AppResult<RlInstall>}      // root, cooked_dir, mods_dir, exe_eac, exe_no_eac
game::fingerprint::{current(install) -> BuildFingerprint}
game::watcher::{subscribe(app) -> tokio::sync::watch::Receiver<RunningState>}

// upk  (owner: engine slice)
upk::keys::KeyRing::load(app) -> AppResult<KeyRing>              // empty ring => KeysMissing error on use
upk::summary::PackageSummary::parse(&[u8]) -> Result<_, UpkError>
upk::rename::{Rename, rename_package(&[u8], &[Rename], &KeyRing, target_key: Option<AesKey>) -> Result<Vec<u8>, UpkError>}  // re-keys for the target name

upk::chunks::{ChunkedBody}                                        // read/patch RL chunked-zlib blocks
upk::package::Body::export_pos(&Export) -> Option<usize>          // via the header's compressed-chunk table
upk::material::texture_params(&Package, &Body) -> Vec<TextureParam> // MIC texture parameter bindings
upk::texture::{extract_thumbnail(path, &KeyRing) -> Result<Option<image::RgbaImage>, UpkError>}

// write layer (owner: foundation)

// palette & decals (owner: engine slice) — called by integrity
palette::reapply_after_update(app) -> AppResult<ReapplyOutcome>
```

Every domain module exposes `pub fn init(app: &tauri::AppHandle) -> AppResult<()>`
(called from `lib.rs` setup; may `app.manage()` its own state and spawn tasks).

## IPC commands (Rust name → TS wrapper in `features/<f>/api.ts`)

Errors always serialize as `{ kind: string, message: string }`.

- `config_get() -> AppConfig` · `config_update(patch: AppConfigPatch) -> AppConfig`

## Front-end conventions

- Routing: code-based TanStack Router (`src/app/router.tsx`). Each feature
  exports a page component from `features/<f>/<Name>Page.tsx`.
- Data: TanStack Query hooks in `features/<f>/queries.ts`, IPC wrappers +
  zod schemas in `features/<f>/api.ts`, using `call()` from `@/lib/ipc`.
- i18n: namespace = feature folder name, files at
  `features/<f>/locales/{en,fr}.json`, auto-loaded by `src/lib/i18n`.
  Shared strings live in `src/lib/i18n/locales/{en,fr}/common.json`.
- Visual layer: pages are made of `GlassPanel`/`GlassCard` on top of the
  global `AuroraCanvas`. Never add another full-screen WebGL canvas; ask the
  `useFx()` store for the accent colour instead.
- The FX layer pauses when the game is in the foreground, when the window is
  hidden/minimised, and respects `prefers-reduced-motion` and the user's
  quality setting (`off | low | high`).

| Slice | Backend | Front-end |
|---|---|---|
| foundation | `base/`, `game/` (minus launch), `lib.rs`, configs | `app/`, `components/`, `lib/`, `stores/`, `styles/`, `features/home`, `features/settings` |
| engine | `upk/`, `palette/`, `decals/` | `features/palette`, `features/decals` |

| play | `maps/`, `stats/`, `extras/` | `features/maps`, `features/play` (launch), `features/tracker` (session, MMR, overlay), `features/extras` |

Slices never edit files owned by another slice. Needed changes to shared
files (`lib.rs`, `Cargo.toml`, `package.json`, `components/ui`) are reported
to the foundation owner, who merges them.

## Conventions every slice must follow

### Rust
- Module layout: `src/<module>/mod.rs` exposes `pub fn init(app: &AppHandle) -> AppResult<()>`
  and `pub mod commands;` holding the `#[tauri::command]` functions listed
  above **with exactly those names**. Internal logic lives in sibling files.
- Commands return `AppResult<T>` (`crate::base::{AppError, AppResult}`). Long
  or blocking work (hashing, decompression, zipping) runs in
  `tauri::async_runtime::spawn_blocking` inside an `async` command.
- Every struct crossing IPC: `#[derive(Serialize)]` +
  `#[serde(rename_all = "camelCase")]`; enums `rename_all = "camelCase"`
  (or `lowercase` for single-word values). Command arguments are written
  in snake_case in Rust and passed in camelCase from TS (Tauri converts).
- Game files are written **only** through `game::writer`
  (`install_file` / `restore_file` / `restore_owner` / `restore_where` /
  `forget` / `audit`), which also refuses to write while the game runs
  (maps excepted, see "Write layer").
- Feature state lives in `base::paths::data_subdir("<feature>")` as JSON,
  read/written with `base::fsx::{read_json_or_default, write_json}`.
- Network only through `base::security::{http_client, ensure_allowed}` with
  the right `Purpose`.
- Unit tests next to the code (`#[cfg(test)]`) for every pure function
  (parsers, planners, codecs). Tests needing real game files are `#[ignore]`.
- No `unwrap()`/`expect()` outside tests except on invariants documented
  with a comment.

### Front-end
- Feature folder: `src/features/<f>/` with `<Name>Page.tsx` (named export,
  see `src/app/router.tsx`), `api.ts` (zod schemas + `call()` wrappers),
  `queries.ts` (TanStack Query hooks + keys), `components/`,
  `locales/en.json` + `locales/fr.json` (namespace `<f>`).
- Shared hooks: `@/lib/game` (`useConfig`, `useUpdateConfig`,
  `useGameStatus`, `useAppInfo`), `@/lib/events` (`useTauriEvent`,
  `EVENTS`), `@/lib/format`, `@/lib/integrity` (`IntegrityReport`).
- UI kit (`@/components/ui/*`, do not modify from a slice):
  `button` (Button: primary|secondary|ghost|outline|danger|success),
  `glass` (GlassPanel, GlassCard — interactive spotlight, `selected`),
  `badge` (Badge tones incl. blue/orange team colours, `dot`, `pulse`),
  `input` (Input, SearchInput), `switch`, `tabs` (controlled, animated),
  `segmented`, `select` (typed options), `slider`, `dialog` (DialogContent
  with title/description/footer), `tooltip`, `feedback` (Skeleton,
  EmptyState, ErrorState, Kbd), `layout` (Page, PageHeader, Section, Field,
  Stat), `toast` (`notify.success|info|error`).
- Visual language: pages = `Page` > `PageHeader` (with a lucide icon) >
  sections of `GlassCard`s. Use accent CSS vars (`var(--color-accent)`,
  `-2`, `-3`), team colours for blue/orange, `font-display` for headings,
  `tabular-nums` for numbers, motion (`motion/react`) for list/entry
  animations (stagger ≤ 40 ms, spring). Keep it dense but airy: this is a
  desktop tool, not a landing page.
- Opening folders: `revealItemInDir` from `@tauri-apps/plugin-opener` only
  (`openPath` is not granted: it could execute files).
- Every string through `useTranslation("<f>")`; EN and FR files must have
  the same keys.
- The overlay window loads `index.html?window=overlay` and renders
  `features/tracker/OverlayRoot.tsx` (named export `OverlayRoot`) without the
  shell, router or WebGL — it must keep its own background transparent.

### Shared payloads defined by the contract

`IntegrityReport` (Rust `integrity::IntegrityReport`, TS `@/lib/integrity`):
`{ gameUpdated: bool, filesReverted: u32, reapplied: string[], pending: string[],
failures: {feature, message}[], checkedAt: RFC3339 }`, emitted on
`integrity://report` after the startup check and after `integrity_reapply`.

`game::ReapplyOutcome` (Rust, returned by each `*::reapply_after_update`):
`enum { NothingToDo, Reapplied, NeedsUser(String) }`.

## Decisions taken while building the slices

- **Stats API** is enabled through the *user* config
  (`Documents\My Games\Rocket League\TAGame\Config\TAStatsAPI.ini`, original
  kept in `data/stats/`), not the install's `TAGame/Config` (checked by EAC,
  and outside `game::writer`'s scope). The client uses the WebSocket
  `WebPort` (49124). `Owner::Stats` is therefore currently unused.
- **Launch with EAC** goes through the store launcher (Epic URI / Steam
  URI) so the game gets its normal authentication; manual installs spawn
  the EAC exe. EAC launch is refused while a custom map is installed.
- **Lethamyr** is browse-only: its downloads redirect to Google Drive,
  which is not on the allowlist. Downloads come from bakkesplugins; the
  SHA-256 the API publishes (`fileHash`) is that of the map package inside
  the zip (`fileName`), so it is checked after extraction.
- **Paint** is not offered on swaps: no painted package variants exist on
  disk (the game applies paint at runtime from the owned item).
- **Custom decals** live in the app's library (`%LOCALAPPDATA%\ALXS-RL-Mod\decals\library`,
  filled by the AlphaConsole import; the AlphaConsole folder is only read) plus
  user-added folders. Pack ids hash `<pack>/<body>` so they survive the import;
  ids of the old full-path scheme still resolve. Bodies and donors
  (`decals::targets`): Octane (paintable GaleFire + hybrid ClassyLady),
  Dominus (hybrid copystripes), Fennec (hybrid bugbite); targets are each
  body's Flames/Stripes/Stars. Hybrid = stock `Body_Paintable_Diffuse_Mat`:
  zone mask R = primary, G = accent, black = art colours; cache
  `AlxsDecal.tfc`; validated in game on the Octane 2026-09-27. AlphaConsole
  masks are converted by `decals::convert`. The renamed donor is re-encrypted
  with the target's AES key: the game picks the key from the package name.
  Universal packs (`BodyID` -1, `1_Diffuse_Skin` + `TrimSheet`) replace an
  esports 2025 universal decal from donor `skin_autobds_00` (cache
  `AlxsUniv*`). All go through `decals::pipeline::build_swap`, which moves
  every other texture of the hijacked cache into ours (read from the stock
  `.tfc` via `game::tfc`).
- **Distribution**: first launch shows a welcome dialog (what the app does,
  the terms-of-use risk, then importing keys.txt) until `onboardingDone`.
  Release builds register `tauri-plugin-updater` (GitHub Releases
  `latest.json`, signed; see `docs/RELEASING.md`). The main window starts
  hidden and is shown in `setup`; `--restore-stock` (run by the NSIS
  uninstaller hook `src-tauri/windows/hooks.nsh`, not on updates) restores
  every owner with `writer::restore_everything` and exits without a window.
- **Custom ball** (`Owner::Ball`): `GameInfo_Soccar_SF.upk` (texture
  `Ball_Default00_D`) rebuilt into `mods/`, cache `AlxsBall*.tfc`; packs in
  `%LOCALAPPDATA%\ALXS-RL-Mod\ball\library`, imported from AlphaConsole's
  `BallTextures` (only packs made for the `Default` ball). Not in presets.
- **Palette grids** follow the in-game picker: 7 rows × 10 columns
  (primary) and 7 × 15 (accent). Blue/orange linking is a UI concern.
- Command signature details differing from the list above (extra `app`
  params, richer return types) are authoritative in each
  `src-tauri/src/<module>/commands.rs` and mirrored in the feature's `api.ts`.
- **Catalog source** is the installed game: `Coalesced_<LANG>.bin` (AES,
  opened with the key ring) holds `Products.*` with every product and its
  EN/FR label, so new seasons appear without an app update
  (`catalog::game_db`). Nothing is bundled: a product's slot comes from its
  asset prefix (`pack_*` bundles from their name) and its id is derived
  from the asset name (FNV-1a, high bit set). Psyonix's numeric product ids
  are not in the local files; the few that matter (bodies, for AlphaConsole
  `BodyID`) are constants in `decals::targets`.
- **MMR** comes from tracker.gg public profiles, loaded in a hidden WebView2
  window (`stats::browser`): a real browser, so Cloudflare is not bypassed.
  The remote page has no capability; results come back through an
  intercepted navigation to `https://alxs-result.invalid/`. Lobby players
  are resolved from the Stats API `PrimaryId` (`stats::lobby`). Reading the
  game's own traffic (what VelocityRL does) is out of scope: it needs a
  trusted MITM certificate and impersonating the game client.
